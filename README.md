## Как выкладывается

- GitHub Pages из ветки `main`, корень репозитория. **Любой push в `main` через минуту-две обновляет тестовый адрес.** Сборки и ключей нет.
- В корне лежит `index.html`, поэтому GitHub Pages показывает сайт, а не этот README.
- Защита от поисковиков: `robots.txt` (`Disallow: /`) и `<meta name="robots" content="noindex, nofollow">` на каждой странице. Новые страницы — тоже с этим тегом.
- Репозиторий публичный: никаких ключей, паролей, данных клиентов и внутренних ссылок.

## Как поменять текст или страницу

1. Правка в `index.html` (тексты) или `site.css` (вид). Наполнение и дизайн берём из макета Figma; анимации, переворот карточек, стекло и подстройку под телефон делаем здесь.
2. После правки стилей поднять номер в ссылке (`site.css?v=…`), иначе браузер покажет старый файл.
3. Commit и push в `main`, проверить на тестовом адресе.
4. Тексты документов — в `privacy.html`, `cookies.html`, `legal.html`. Пометки `[уточнить]` заменить реальными данными, блок «Черновик» убрать только после вычитки юристом.

## Статьи и «О нас»

- Новая статья: файл `source/stati/<slug>.md` по `FORMAT.md` (рубрика из списка, картинка из `img/`, источник из базы знаний), затем `python3 source/build_stati.py`, commit, push в `main`.
- Факты в статьях — только из базы знаний Notion и справки о продукте; при расхождении побеждает справка. Сроки красной карты в источниках разные, поэтому в статьях без точной цифры.
- Метки на бота: список статей и плашка базы знаний — `site_articles_kb`, кнопки в статье — `site_art<slug>_chances`, «О нас» — `site_about_chances` / `site_about_questions`.
- Внутренние страницы подключают `glass.js` с `data-home` (путь до корня, у статей `../`) и `data-page` (активная вкладка нижнего меню на телефоне) на `<html>`.

## Форма заявки

- Форма в блоке «¿Empezamos?» (`index.html`, `#apply`) отправляет заявку в CRM: `POST https://crm.asilohelp.com/site/lead` (JSON: `name`, `contact_type` telegram|email, `contact`, `interest`, `about`, `consent`, `sensitive_consent`, `token`, `website`, `page`). Код приёма — репозиторий `rkhmanov/asilo-bot`, файл `cloudflare/src/sitelead.ts`. Ответ: номер заявки вида `W-1126-01`, его видит человек.
- Защита от ботов: Cloudflare Turnstile, sitekey `0x4AAAAAAGN1oWk5fZGZETVJ` (публичный, не секрет), плюс скрытое поле-ловушка `website`. Секретный ключ Turnstile — только на сервере CRM, здесь его нет.
- Проверка полей — в браузере (имя, Telegram `@username` или телефон `+…`, e-mail, до 2000 знаков о ситуации, обязательная галочка согласия — по умолчанию не стоит). Ошибки сервера (400 / 403 / 429 / 5xx) показываются над кнопкой, заполненная форма не стирается.
- На `localhost` Turnstile не проходит (домен не разрешён) — отправку проверяют на тестовом адресе GitHub Pages.

## Чем отличается от боевого сайта

- Боевой сайт asilohelp.com — отдельный закрытый репозиторий `rkhmanov/asilohelp-site` на Cloudflare. Там пока старая главная.
- Здесь — новый дизайн по макету Figma, своя вёрстка и стили. Общего кода нет, автоматического переноса нет.
- Перенос на бой — вручную: готовые файлы копируются в `public/` боевого репозитория, убираются `noindex` и пометки «тестовая версия», выкладка — только с явного согласия владельца.
