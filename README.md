## Как выкладывается

- GitHub Pages из ветки `main`, корень репозитория. **Любой push в `main` через минуту-две обновляет тестовый адрес.** Сборки и ключей нет.
- В корне лежит `index.html`, поэтому GitHub Pages показывает сайт, а не этот README.
- Защита от поисковиков: `robots.txt` (`Disallow: /`) и `<meta name="robots" content="noindex, nofollow">` на каждой странице. Новые страницы — тоже с этим тегом.
- Репозиторий публичный: никаких ключей, паролей, данных клиентов и внутренних ссылок.

## Проверка перед мержем

`node tests/qa.cjs` (нужен пакет `playwright`; `--shots` — скриншоты во `tests/shots/`, `--only=page.html` — одна страница). То же самое запускает GitHub Actions («Проверка сайта») на каждый PR и push в `main`, скриншоты — в артефакте `screenshots`. Что проверяет, по всем `*.html` (кроме `source/`, `vendor/`):

- `noindex` и `viewport` на каждой странице, нет повторяющихся `id`;
- локальные ссылки и картинки ведут на существующие файлы, якоря `#…` есть на странице;
- ссылки на бота несут метку `site_<место>[_<цель>]` (см. ниже);
- в Chromium на ширине 360, 390, 768 и 1440: нет ошибок JavaScript и битых файлов, нет горизонтальной прокрутки, все блоки с анимацией появления (`data-reveal`) показываются.

## Метки ссылок на бота

Каждая ссылка на @ASILOhelperBot — с меткой, чтобы CRM видела, какая кнопка сайта привела человека (CRM → Аналитика → «Откуда клиенты»). Формат `https://t.me/ASILOhelperBot?start=site_<место>[_<цель>]`, только латиница, цифры и `_`. Цель открывает нужную анкету в боте: `chances`, `questions`, `general`, `consult`, `caseconsult`, `interview`, `case`, `sopr`, `kb` (список — `DEST` в `asilo-bot/cloudflare/src/sources.ts`); без цели — главное меню. Место не должно совпадать со словом цели.

Сейчас: `site_header` (кнопка «Telegram-бот» в шапке), `site_ruki_chances` («Оценить шансы» на первом экране `glavnaya-ruki.html`), `site_kb` (база знаний), `site_guide_kb` (главный гайд в «Новостях»), `site_faq_questions` (вопросы), `site_apply_chances` (бот рядом с формой), `site_formok` (после отправки заявки), `site_docs` (страницы документов).

## Как поменять текст или страницу

1. Правка в `index.html` (тексты) или `site.css` (вид). Наполнение и дизайн берём из макета Figma; анимации, переворот карточек, стекло и подстройку под телефон делаем здесь.
2. После правки стилей поднять номер в ссылке (`site.css?v=…`), иначе браузер покажет старый файл.
3. `node tests/qa.cjs`, затем commit и push в `main` (или PR), проверить на тестовом адресе.
4. Новая внутренняя страница: скопировать `keys.html` (шапка, подвал, форма уже на месте), подключить `inner.css`, поменять метки бота на `site_<место>_<цель>` (цель — слово из `DEST` в `asilo-bot/cloudflare/src/sources.ts`, иначе бот откроет главное меню).
5. Тексты документов — в `privacy.html`, `cookies.html`, `legal.html`. Пометки `[уточнить]` заменить реальными данными, блок «Черновик» убрать только после вычитки юристом.

## Статьи и «О нас»

- Новая статья: файл `source/stati/<slug>.md` по `FORMAT.md` (рубрика из списка, картинка из `img/`, источник из базы знаний), затем `python3 source/build_stati.py`, commit, push в `main`.
- Факты в статьях — только из базы знаний Notion и справки о продукте; при расхождении побеждает справка. Сроки красной карты в источниках разные, поэтому в статьях без точной цифры.
- Метки на бота: список статей и плашка базы знаний — `site_articles_kb`, кнопки в статье — `site_art<slug>_chances`, «О нас» — `site_about_chances` / `site_about_questions`.
- Внутренние страницы подключают `glass.js` с `data-home` (путь до корня, у статей `../`) и `data-page` (активная вкладка нижнего меню на телефоне) на `<html>`.

## Чем отличается от боевого сайта

- Боевой сайт asilohelp.com — отдельный закрытый репозиторий `rkhmanov/asilohelp-site` на Cloudflare. Там пока старая главная.
- Здесь — новый дизайн по макету Figma, своя вёрстка и стили. Общего кода нет, автоматического переноса нет.
- Перенос на бой — вручную: готовые файлы копируются в `public/` боевого репозитория, убирается `noindex` (плашки «Тестовая версия» на страницах нет с 23.11.2026: защита — `robots.txt` и `noindex`), выкладка — только с явного согласия владельца.
